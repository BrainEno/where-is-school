# 游戏内剧情作者版

作者版是独立的游戏副本。它加载同一间教室、同一个 NPC 和同一套对白面板。iPhone 普通测试包也带同一套编辑器运行时，但**默认关闭**：在「设置 → 编辑模式 → 剧情编辑」打开开关后，暂停菜单才出现「剧情编辑」，关闭开关后入口消失。桌面发行包与 Android 包不含编辑器；桌面开发时可直接在项目内启用，或运行下方隔离的作者版。作者版的设置和草稿都不与普通版共用；编辑器的草稿与「文件」桥接放在 `user://story_editor/`。

设置先写入同目录的独立临时文件并读取核对，再保留旧文件、发布新文件。旧版留下的 `settings.cfg.tmp` 不再阻塞写入；如果发布中断，游戏可以读取 `settings.cfg.bak` 中的上一次设置。真实写入失败时开关不变，不必清除应用数据或卸载游戏。

## 桌面启动

安装仓库 `.godot-version` 指定的标准版 Godot 和 Python 3。首次准备需要导入资源。若 Linux 上新输入的汉字缺字，请安装 Noto Sans CJK 等系统字体。

```sh
python3 tools/authoring_build.py --godot godot --output builds/author-project
```

命令复制 Git 跟踪的游戏资源到新的空目录，不改普通项目或已发布对白。之后可直接 `godot --path builds/author-project`。新版本用另一个空目录准备，草稿从同一个作者版数据目录读取。请勿同时启动两个作者版实例编辑同一份草稿。

## 编辑、试走、导出

1. 进入游戏，对教室的坐姿同学发起对话。`prologue / student / st_reciting` 有原来的两个选项。点击「剧情编辑」，会停在当前对白；继续浏览其他台词后可用「当前台词」定位回来。也可以按章、会话和节点选择，或用「查找」跨章节搜正文、选项和 ID（包括说话人 ID）。查找不改变正在编辑的字段；选择结果才会跳转。
2. 编辑正文，或从「文案」选择原选项。在 iPhone 点「编辑这个字段」，用系统输入法在游戏旁的文本窗口输入，点「应用」；查找也走同一输入法。游戏暂停，旁边的对白是**独立预览**。标题标明原文或草稿；对照原文不改写原文，提交新输入会回到草稿预览。作者稿当前只编辑简体中文数据，但输入可用其他语言字符。
3. **给已有选项写下一轮**：从「文案」选择具体选项，点「添加后续」。一轮可写 1–12 句，每句可选本会话已有的说话人；不确定的句子勾「本句先占位」，备注可留空。「加一句」继续写，用「后续句」切换；点「保存新增」才接到该选项。不同选项各走各的新增段落，末句接回各自原去向（包括原来的结束路线），不改其他选项。已加过的选项可「追加后续」，新段排在前一轮之后。
4. **补写与试走**：选回那个选项，点「查看后续」跳到它的第一句；其余新增句也可在「节点」逐句选择、改文案。选中占位句时，正文输入框是空的；填入正文会替换占位，原有连接不变。「从头试走」从会话入口验证全路；「本句试走」可直达选定节点，沿用当前旗标，不补跑前文条件或效果。选「看原文」后试走仍用原线路；草稿新增节点在原文中无对应位置。试玩使用旗标和知识副本，不写真实存档、已读、任务或背包；点「返回编辑」继续调整，「回游戏」恢复原对白。
5. 原有「插句／加选项」仍在：在普通节点后插句，或在已有普通选择点新加选项，接已有节点或一条新回应。已经属于某个选项的后续句不会作为别的选项的接入点。当前后续是同一会话内的一段对白，不新建独立会话、NPC 绑定、可选分支点、条件、检定或世界事件。
6. 校验通过的文案会自动保存；「保存文字」可立即保存。空白或超长输入留在表单内，不更新预览；改好后再保存，或点「放弃输入」恢复到已应用的文案。「保存新增」前的多句表单可从本机草稿恢复。若本机写入失败，可重试；也可在确认后暂回游戏，重新打开编辑器继续。**暂离不是保存**：关闭编辑模式或退出应用会丢失尚未写入的内容。一份草稿损坏而从另一份恢复时会提示。
7. 点「导出 JSON」。桌面选择新的 `.json` 文件（不覆盖已有文件）。iPhone 在「文件」选择「在我的 iPhone」也可离线保存；仅复制这一个 JSON，不共享存档目录。若有未应用的输入，按钮改为「导出已应用」，不包含那部分输入。新游戏不清空草稿；4 秒内按两次「清空」才重置，可在本次会话撤销。重要修改可先导出备份。没有自动同步；新版可读原来的 v1 草稿。带后续的草稿使用 v1 的 `followup` 操作，需要支持该操作的作者版和预检工具。

## 电脑预检作者稿

```sh
python3 tools/review_author_draft.py /path/to/where-is-school-dialogue-draft.json \
  --godot godot --output builds/author-review
```

不指定 `--output` 只预检。**有未补写的占位时**，预检会验证连接并提示待补写数量；指定输出目录只得到 `pending_followups.json`（章、会话、原选项、占位句 ID、说话人和备注），不生成可误用的候选对白。补写后重新导出。不含占位时，新空目录会得到候选中英文 JSON、`preview.diff` 和 `pending_en.json`。

预检按原字段、原选项结构与去向检查冲突；同一字段在别处改过、锚点不再存在或所选分支已改线时拒绝，不覆盖。英文副本复用现有译文；待译处不当作最终译文。确认差异、完成待译、跑剧情校验／中英结构测试和字库检查后，才按 [故事文档流程](../../docs/STORY_DOCS.zh-CN.md) 审核候选文件。工具不会修改仓库对白或 Google Docs。

## iPhone 构建与验收

作者版 Bundle ID：`io.github.braineno.whereisschool.authoring`，和普通版可并存。iPhone 普通测试包（`io.github.braineno.whereisschool`）同样链接 Files 桥接，因此开关打开后可直接用系统输入法编辑、用「文件」导出草稿。CI 的 macOS 测试校验两版的无签名归档（都不是可安装 IPA）、设备版的 Files 桥接和普通版的编辑器开关。**CI 通过后**才从通过检查的干净提交，在受信任的 macOS + Xcode 环境签名；使用明确匹配该 Bundle ID 的 Development 或 Ad Hoc 描述文件，并包含目标设备。项目已有 `sign_ipa.py` 的三个受保护输入仍从私密环境提供；不要用聊天、PR 或公开构件传签名材料及设备描述文件。公开 `build-ios.yml` 的保护规则不变，不用它发作者版私密 IPA。

```sh
python3 tools/macos/ios/sign_ipa.py --authoring --distribution development \
  --build 1 --output builds/author-ios-signed
```

`--build` 使用实际递增值；可换成 `--distribution ad-hoc` 并配置对应签名。签出的结果先核对 `BUILD.json` 的 `head`、`bundle_id`、`modified_sources` 与 `sha256`，只私下交付 `.ipa`。模拟器 `.app` 和无签名 `.xcarchive` 都不能当作手机安装包。

实体机核对：在保留已有存档、语言与音量的前提下升级，打开开关、重启并从暂停菜单进入；飞行模式下试两种横向握持；拼音／注音查找、在句中选区替换、换行、粘贴、收键盘；从头和从本句走两个原选项的各自后续；写占位备注、补写；「应用」并保存后强退重开；「文件」选本机目录保存、取消及在电脑运行预检；退出编辑后原游戏与方向控件正常。系统输入窗口内尚未点「应用」的内容不保证强退后恢复。自动测试的安全区和无签名归档不能代替这些项。

## 编辑边界和后续缺口

- 实时改动进入隔离预览和试走，不热替换正在进行的游戏对白，也不自动改仓库或 Google 文档。游戏内界面不编辑英文、物件检查、硬编码演出、条件／检定或角色绑定；这些仍走各自的数据或审阅流程。
- 没有可编辑的全图、逐项删除／重排任意既有结构、重做历史或设备间导入。新增后续、插句和加选项仍受图校验约束；撤销只保留本次工作区的有限历史。
- 更新版本后遇到已应用操作与游戏原文冲突时，编辑器不覆盖原文；可导出原草稿到电脑核对。未确认的新结构不属于可移植操作；跨版本前建议先应用或手动备份表单。iOS 的系统输入与「文件」依赖包内原生桥接。
