# Asset pipeline — imported 3D models

This note is the contract for the first non-primitive asset a location is allowed to
contain: a glTF 2.0 model that came from outside the engine. It exists because the
repository had no model of any kind — everything 3D in it is Godot primitive boxes,
either authored in a `.tscn` or emitted by `tools/build_outdoor_locations.py` — so the
first real export from Blender would have arrived with an unknown scale, an unknown
forward axis, an unknown pivot and no collision, and nothing in CI would have noticed.

Two placeholder samples now prove the pipeline end to end. They are **not art**: they
are boxes with materials, written by a checked-in script, waiting to be replaced (see
[ASSET_PROVENANCE.md](ASSET_PROVENANCE.md)).

| | File | Placed in the game | Wrapper | Collision |
|---|---|---|---|---|
| Chair | `assets/models/sample/chair.glb` | yes, the courtyard's south-east corner | `scenes/environment/props/sample_chair.tscn` | `BoxShape3D` 0.52 × 0.92 × 0.52 |
| Figure | `assets/models/sample/figure.glb` | **no**, deliberately | `scenes/environment/characters/sample_figure.tscn` | `CapsuleShape3D` r 0.30, h 1.72 |

The figure is not standing in any location. Adding a person to a scene is a narrative
decision, and this pipeline round is not allowed to make one.

## 1. The model contract

A runtime model is one `.glb` file and nothing else. Lightmaps, `.blend` files, and
texture sources stay out of `assets/`; the runtime file is a build artefact.

| Rule | Why |
|---|---|
| glTF 2.0 **binary** (`.glb`) | one file, no side-car `.bin` or `.gltf` to lose; Godot imports it as a scene without an add-on |
| **1 unit = 1 metre** | every number in this project is metres: doors are 2.1 m, the agent is 1.8 m high, `agent_max_climb` is 0.3 m |
| **+Y up**, model **faces -Z** | the same axes the engine and the camera use; a model that faces +Z walks backwards. The two authored characters in the tree do not meet this yet — see §10.2 |
| **origin at the floor, on the model's centre line** | placement code writes a position on the ground and gets the object standing there; no per-instance offsets |
| **no node scale**, no rotation baked into nodes | a 0.01-scaled export passes a size check in the viewport and then behaves like a different object in code |
| **one material per mesh**, named after the asset | a placeholder material is easy to replace when its name is stable |
| normals included; tangents only with a normal map | the graybox lighting is flat and cheap, and unused tangents are bytes |
| **no cameras, no lights, no empties** in the file | the engine scene owns the environment |

The samples are built to a rounded-part box budget on purpose: under 500 triangles and
under 8 KB each. A placeholder that is expensive to look at is a placeholder nobody
replaces.

Half of this table is now checked mechanically: `tools/model_library.py --check` reads
every `.glb` under `assets/models/` in CI and fails on a camera, a light, a scaled or
matrix node, a file over the model budget of §9.1, embedded images over a texture budget,
or a model whose `.import` sidecar is missing or stale. What it cannot judge — facing,
triangle count, where the origin sits — is recorded per model in
[MODEL_LIBRARY.md](MODEL_LIBRARY.md) instead.

## 2. What the model does *not* carry

Collision, interaction and navigation are **not** part of the model. They live in a
wrapper scene, because a glTF file cannot say "the player may stand here" and because
the wrapper is the thing a designer drags into a room:

- the wrapper root is a `StaticBody3D` on **physics layer 1**, the layer
  `LocationNavigation` reads when it bakes. Collision on another layer is a prop the
  player bumps into and the path-finding walks through — the exact mismatch this
  pipeline exists to prevent;
- exactly **one** `CollisionShape3D`, sized to the visual bounds (within 2 cm), resting
  on the floor;
- the model is instanced as a child named `Model`;
- a character-sized wrapper also carries an `InteractionAnchor` `Marker3D` at chest
  height (1.2 m), which is where a future `Interactable` goes — the model itself has no
  idea where its own conversation would be.

## 3. Where files live

| Path | Owner | Regenerated by |
|---|---|---|
| `assets/models/<kind>/<name>.glb` | the artist, exported | `tools/build_sample_models.py` for the two samples only |
| `scenes/environment/props/*.tscn`, `scenes/environment/characters/*.tscn` | hand-authored wrapper | **nothing** — no script writes these |
| `scenes/locations/<location>/*.tscn` | `tools/build_outdoor_locations.py` | that script, every run |

A wrapper must never live under `scenes/locations/`: those four outdoor scenes are
rewritten from a box table on every run of the generator, so a hand edit there is
deleted without a diff.

`<kind>` is the place a model is instanced — `classroom/`, `corridor/`, `playground/`,
`protagonist/`, `q/` — so the model tree has one folder per location that draws from it,
and the file name repeats the kind (`classroom_student_desk.glb`) so that a search for
`classroom_` returns the model, its wrapper, its test and its provenance row together. A
model has exactly one home; a second room instances the wrapper, not a copy of the file.
[`MODEL_LIBRARY.md`](MODEL_LIBRARY.md) is the inventory: every model, its kind, its size,
its triangles and where its origin sits, printed from the files themselves by
`tools/model_library.py --report`.

## 4. Placing one

A placement is a line in the generator's table, not a node added in the editor:

```python
s.props = [
    ("SampleChair", "res://scenes/environment/props/sample_chair.tscn", (10.3, 0.0, 13.5), 26.0),
    ("CourtyardBench", "res://scenes/environment/props/playground_bench.tscn", (-3.2, 0.0, 6.0), 180.0),
]
```

The generator writes an `ExtResource` instance with that position and rotation, and
leaves the wrapper alone. The rotation is a yaw in degrees: the table has no room for a
tilt, which doubles as a guard against a prop being dropped in sideways. Regenerating the
location therefore keeps the hook-up, and `tests/model_import_test.gd` (the samples) and
`tests/prop_placement_test.gd` (the authored props) fail if the table line, the wrapper,
or the instance ever disappears.

A placed prop is furniture: it collides, so it carves the navigation mesh and it blocks
the interaction line-of-sight probe. A look-anchor for that prop therefore has to stand
off its own collision, or be listed in the interactable's `support_paths` — an anchor in
the middle of a bench is a hotspot no standing position can see.

Place a prop where it does not carve the walkable space in two and where it cannot hide
an interactable: the agent radius is 0.4 m, so a 0.5 m prop erodes a hole about 1.3 m
across in the baked mesh.

## 5. Regeneration and provenance

```bash
python3 tools/build_sample_models.py          # write the two .glb files
python3 tools/build_sample_models.py --check  # fail if the committed bytes differ
```

CI runs `--check`, so the committed binaries cannot drift from the script that is their
provenance. Every model, sample or real, is recorded in
[ASSET_PROVENANCE.md](ASSET_PROVENANCE.md) with its source, licence, and modifications.

## 6. For a real Blender export

The version of Blender is the owner's decision; this table is what the export has to
produce, whatever the version:

| Setting | Value |
|---|---|
| Format | glTF 2.0, binary (`.glb`) |
| Transform | apply scale and rotation; +Y up, forward -Z ("-Z Forward, Y Up" in Blender's export panel) |
| Origin | at the floor, centred on the footprint (place the 3D cursor there and set origin to cursor) |
| Objects | only the mesh: no cameras, no lights, no empties |
| Modifiers | applied (the exporter does not apply them for you) |
| Materials | one per mesh, named for the asset; embedded in the `.glb` |
| Source file | kept outside `assets/` and outside this repository unless the owner says otherwise; the source path and version are recorded in the ledger |

## 7. How the pipeline is verified

`tests/model_import_test.gd` (headless, every pull request):

1. each `.glb` imports as a scene, with a mesh, a surface and a material;
2. its bounding box matches the size declared for it within 2 cm, its origin is within
   1 cm of the floor and of the centre line;
3. no node in the imported scene carries a scale other than 1;
4. each wrapper is a `StaticBody3D` on layer 1 with exactly one shadow-casting-shaped
   collider, covering the model's height, with the model instanced inside it;
5. the placed chair stands on the courtyard floor, within 1 m of walkable ground, does
   not cut the courtyard's route to the alley, and is still requested by the generator
   table;
6. both sample names appear in this document and in the provenance ledger.

`tools/build_sample_models.py --check` runs in CI as well: the committed binaries are
reproducible from the script.

`tools/model_library.py --check` covers the half of §1 that no engine test looks at: it
parses every `.glb` under `assets/models/` and fails on a camera, a light, a scaled or
matrix node, a file over the model budget, embedded images over the texture budget, or a
missing/stale `.import` sidecar. `tests/model_library_test.py` checks the checker against
files it writes itself, on both sides of every limit.

### The import pass is part of the contract

Asset metadata (`.import`, `.uid`) is tracked in this repository. That changes what an
import pass has to do, because a tracked sidecar makes the engine resolve an asset
through `.godot/imported/…` and stop falling back to the source file:

- CI imports with `godot --headless --path . --import`, which waits for the import
  queue to drain. `--editor --quit` returns after one frame, while the first scan is
  still running on its worker thread, and with sidecars in the tree that leaves every
  binary asset unresolvable even though the import "succeeded".
- The `import audit` step in `.github/workflows/godot-ci.yml` then reads the
  `res://.godot/imported/…` paths out of each `.import` and fails when one is missing,
  so a silent gap fails at the import instead of as a confusing size check later.
- `art/` holds the editable sources (`.blend`) and is excluded from the resource
  filesystem with `art/props/.gdignore`: Godot's `.blend` importer needs a Blender
  binary, and neither a clean checkout nor CI has one.

## 8. Not in this round

- Character locomotion is supplied by the project's code-authored idle/walk/jog clips and
  wrapper-level animation driver; the GLBs do not embed animation actions. No LOD or
  lightmap UVs yet.
- **No performance budget.** A triangle budget for a prop, a character or a room needs
  a measurement on the target Windows machine, and none has been made. The numbers in
  this document are placeholder sanity limits for the graybox, not a performance claim.
  The build-size budgets in §9 are about bytes on disk, which can be measured anywhere,
  and are not a frame-time claim either.
- No Windows hands-on pass over the placed chair.

## 9. Build size: what a release may carry

`tools/verify_build.py` reads the pack back out of the exported executable and checks it
against the tables below. It is the only check that inspects what a player would actually
receive: the export preset is a wish list, the pack is the truth.

### 9.1 Categories and their limits

Every packed file is classified by the kind of thing it is, and measured against that
kind's budget. Classification reads the *source* extension out of the stored name, because
an imported resource is packed as
`.godot/exported/<hash>/<source name>-<hash>.<ext>` — so `student_backpack.glb-5817e7e.scn`
is a model, not a scene.

| Kind | Warning | Hard limit | Why those numbers |
|---|---|---|---|
| model | 384 KiB | 1.5 MiB | the two sample meshes pack at 206 KiB and 134 KiB; 1.5 MiB means an untrimmed Blender export or a texture baked into a mesh |
| font | 384 KiB | 1 MiB | the subset covering every character the game can print is 252 KiB; 1 MiB means the full 10 MiB source font, or a subset without its glyph range, got packed |
| texture | 512 KiB | 2 MiB | none ships yet; 512 KiB is a 1024×1024 RGBA image, 2 MiB is a photograph used as a wall |
| audio | 512 KiB | 2 MiB | the placeholder cues are a few KiB each; past half a megabyte is a music track or an uncompressed recording |
| scene | 192 KiB | 1 MiB | the largest location scene packs well under 100 KiB; a 1 MiB `.tscn` has embedded resources in it |
| text | 128 KiB | 512 KiB | the largest dialogue or inspection chapter is about 10 KiB; 512 KiB is a whole corpus in one file |
| other | 256 KiB | 2 MiB | project settings, pack stubs, imported banners; something over 256 KiB here is something nobody classified |

**No hard limit is above 2 MiB.** That was the old flat per-file rule, so this table can
only tighten it. The pack total keeps its **16 MiB hard limit** and gains an **8 MiB
warning line**: the baseline is 1.37 MiB, so the hard limit leaves room for roughly eleven
times today's content, while a release that doubles gets a warning before it doubles again.

**A warning does not fail the release; a hard limit does.** Warnings are printed and
attached to the workflow run as annotations, which is where a build that has grown should
be visible while it is still cheap to fix.

### 9.2 What the report looks like

```
by category (warn / hard):
  model       2 file(s)   340 KiB  [384 KiB / 1.50 MiB]  ok  largest: bench_playground.glb-... 206 KiB
  font        2 file(s)   252 KiB  [384 KiB / 1.00 MiB]  ok  largest: NotoSansSC-Regular.ttf-... 252 KiB
  ...
```

One line per kind of asset, with the largest file of that kind next to it: a pack that
doubled is either one heavy kind or a little of everything, and this answers which without
reading a listing of 256 paths.

### 9.3 What must not be in a build

`docs/` (including the captured screenshots), `tests/`, `tools/`, `art/`, `addons/` and
`.github/` are **forbidden prefixes**: a single file under any of them fails the release.
The `.blend` sources under `art/` are additionally kept out of Godot's own resource
filesystem by `art/props/.gdignore`, because the `.blend` importer needs a Blender binary
that neither a clean checkout nor CI has. `scenes/main/main.tscn`, the theme, both
languages of dialogue and inspections, the audio directory and the font stub are
**required prefixes**: their absence fails the release too, because a build that starts
without the game in it is worse than a big one.

### 9.4 How it is tested

`tests/verify_build_test.py` runs in CI on every pull request and needs no engine: 75
boundary checks over the classification of the exporter's hashed names, **both sides of
every warning line and every hard limit**, the pack total at its limit and one byte over,
the forbidden and required folders, and the pack reader itself, against synthetic v2, v3
and v4 packs — including an embedded pack with a decoy `GDPC` after it, which is the case
that made the first version of the reader report a build with no files in it.

## 10. The imported production assets

Round two of the pipeline imported the four assets a scene is now allowed to be built
from: two Poly Haven CC0 props and the owner's two characters. They follow the same
shape as everything above — a `.glb` under `assets/models/<name>/`, a hand-authored
wrapper under `scenes/environment/` — with the deviations in §10.2 written down instead of
hidden. The companion record is
[IMPLEMENTATION_NOTES_IMPORTED_MODELS.md](IMPLEMENTATION_NOTES_IMPORTED_MODELS.md), and
`tests/imported_assets_test.gd` measures every number below.

### 10.1 What is there

| Asset | Runtime file | Wrapper | Size X × Y × Z (m) | Triangles | Wrapper root |
|---|---|---|---|---|---|
| School desk | `assets/models/school_desk/school_desk.glb` | `scenes/environment/props/school_desk.tscn` | 0.712 × 0.883 × 0.546 | 4,162 | `StaticBody3D`, layer 1, one box |
| Stationery supplies | `assets/models/stationery_supplies/stationery_supplies.glb` | `scenes/environment/props/stationery_supplies.tscn` | 0.302 × 0.164 × 0.084 | 4,412 | `Node3D`, no collision |
| Protagonist | `assets/models/protagonist/Protagonist_Character.glb` | `scenes/environment/characters/protagonist.tscn` | 1.046 × 1.767 × 0.324 | 15,782 | `Node3D` + `InteractionAnchor`; 60-joint rig, A-pose (PR #118) |
| Former protagonist (classroom student) | `assets/models/protagonist/protagonist.glb` | `scenes/environment/characters/classroom_student.tscn` | 0.556 × 1.727 × 0.337 | 12,388 | `Node3D`, `start_seated`, model at y = −0.347; no anchor, no collision |
| Q | `assets/models/q/q.glb` | `scenes/environment/characters/q.tscn` | 0.726 × 1.647 × 0.607 | 35,432 | `Node3D` + `InteractionAnchor`; 16-bone rig |

A prop wrapper is the §2 wrapper: `StaticBody3D` on layer 1, exactly one box collider
sized to the visual bounds, the model as the `Model` child. A character wrapper is a
visual, not a body — the asset reports no collision, and whichever controller drives the
character owns the capsule — so it is a `Node3D`, a `Model` child, and an
`InteractionAnchor` at chest height so nobody re-derives that per character. A decoration
wrapper carries no collision on purpose: desk dressing sits on furniture that already
collides, and a 0.16 m prop with its own collider would carve a hole in the baked
navigation mesh. A seated character wrapper (the classroom student) is a character visual
that opens in `sit_idle` (`CharacterVisualAnimation.start_seated`) with its model lowered
so the seated soles meet the wrapper's floor; it has no anchor, because nothing interacts
with it.

### 10.2 Three deviations, recorded rather than hidden

1. **The two characters face +Z, not −Z.** §1 asks for −Z forward, and the two
   Blender-born characters — like the playground bench before them, whose back
   `IMPLEMENTATION_NOTES_PROPS.md` records as sitting on its own −Z side — were authored
   facing the other way: their eyes are on the +Z side. The wrapper deliberately does
   **not** correct this with a baked 180° yaw, because a wrapper yaw is a second place
   the facing is written and it breaks the moment the GLB is replaced. Placement yaws
   180° instead, exactly as the bench is handled, and `imported_assets_test.gd` fails if
   the eyes ever move to the other side. "At placement" is two different places, because
   the two drivers were written against different conventions: `PlayerController` turns
   the model with `atan2(facing.x, facing.z)`, which is a +Z model's angle and needs no
   correction, while `NpcActor.face_towards()` adds PI for a −Z model, so an `NpcActor`
   with a `visual_scene` turns the instantiated visual 180° (`visual_yaw_degrees`, default
   180). Adding both would cancel out, and the character would walk backwards while every
   size still measured right — `imported_placement_test.gd` checks where the model points,
   not just which angles were written. §1 remains what a *new* export should produce; it
   is not what these two files do. **Owner decision needed:** re-export the characters
   facing −Z, or adopt "authored characters are yawed at placement" as the rule.
2. **The stationery does not stand on a floor.** Its own origin is the middle of the
   arrangement — its lowest point is 7.4 cm below it — so the raw GLB is not drop-in
   placeable. `stationery_supplies.tscn` re-origins it to its base, which is why the
   wrapper, not the model, is what a scene instantiates.
3. **`q.glb` no longer carries a node scale.** It used to: the collar was authored at
   1 × 0.7 × 0.9 on its node, the one exception to §1's "no node scale", and the test
   recorded it by node name so a second one could not appear unnoticed. The rigging pass
   that gave Q its 16-bone armature baked that scale into the collar's vertices, so the
   exception is gone and the record is empty — the size, base and facing assertions above
   did not move, which is the evidence that the bake changed nothing on screen. The
   former protagonist's origin sitting 1.7 cm above its sole is still recorded at 5 mm
   tolerance, so a re-export that moves it fails the test rather than a placement. The
   protagonist that replaced it (PR #118) stands on its origin.

### 10.3 Textures are embedded, not extracted

The engine's default for a `.glb` with embedded textures is `gltf/embedded_image_handling
= Extract Textures`, which writes `<glb>_<texture>.jpg` and a matching `.import` next to
the model. That would put derived files inside `assets/` and contradict §1's "one `.glb`
file and nothing else", so the two textured assets set `gltf/embedded_image_handling = 2`
(Embed as Basis Universal) in their committed `.import` sidecar: the maps live inside the
imported scene, the model directory holds only the `.glb` and its sidecar, and
`imported_assets_test.gd` fails if anything else appears there.

Embedding is GPU-native but not free in bytes, and the imported scene is what the release
build packs: `tools/verify_build.py` rejects any single packed entry over 2 MiB. So the
Poly Haven 1K maps were resampled to 512 first. At 512 the two imported scenes are 0.7 MB
and 0.9 MB; at 1024 they were 2.0 MB and 3.2 MB, which the release build would have
rejected. The resample is recorded in [ASSET_PROVENANCE.md](ASSET_PROVENANCE.md) and no
geometry, UV or material was touched.

### 10.4 `scenes/dev/` is not a resource

`scenes/dev/` holds development-only previews, `imported_assets_preview.tscn` among them.
`export_presets.cfg` excludes it from the export and `tools/verify_build.py` now fails if
anything under `res://scenes/dev/` reaches a build, the same guard `res://addons/` has.

### 10.5 Where the four are used

A wrapper nobody instantiates is an asset with no screen time, so the library has a
placement as well as a contract:

| Wrapper | Instance | Notes |

| `props/stationery_supplies.tscn` | `classroom.tscn` → `Furniture/DeskB2/Stationery` | one instance, on the player's own desk, no collision. |
