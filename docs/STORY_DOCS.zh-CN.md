# 故事文档（台本）：格式与往返流程

> **状态：** 现行
> **最后核对：** 2026-11-19
> **负责人：** 内容 Agent
> **取代者：** 无；内容契约本身见 [data/dialogue_schema/README.md](../data/dialogue_schema/README.md)，用词见 [GLOSSARY.md](GLOSSARY.md)

游戏里的每一句话都存在 `data/dialogue/` 与 `data/inspections/` 的 JSON 里。JSON 精确，但不适合写作者直接改。`tools/story_doc.py` 把**中文**内容导出成一组可读的台本（每份一个 Google 文档），写作者改完放回原处，再由它导回 JSON。英文不在台本里：导入后按 `pending_en.json` 补译，保证两种语言结构一致。

## 1. 一套台本有哪些文档

| 文档 | 内容 | 可改 |
|---|---|---|
| `00_剧情安排` | 序章节拍、17 个地点、路由（谁在什么条件下说哪段）、内心声音被动规则、每个 flag 由谁写谁读、待决问题；末尾「◆ 界面文字」是目标条、地名、结束卡 | 只有「◆ 界面文字」一节可改，而且只能改已有键的文字 |
| `01_对话_prologue` … `08_对话_inner_voice` | 八个对话章节，顺序与游戏流程一致：prologue、corridor、school_annexes、street、residential、alley、playground、inner_voice | 文字与结构都可改 |
| `09_检视文字` | 17 个地点的全部检视物 | 文字与记录可改 |

「剧情安排」由代码与数据现场生成，所以永远和游戏一致；它不导回。想改编排（触发时机、谁在场、节拍顺序）就在文档里写批注，那是代码改动。

## 2. 对话台本怎么读

```
■ 会话 pg_shed
※ 触发：路由 pg_shed（场景 playground）条件：无条件
属性：默认来源 亲眼所见｜主观 否｜起点 ps_1
[ps_1] 旁白：器材棚有扇绿门，门上装着搭扣，还挂着一把锁。
[ps_2] 旁白：你可以试试门，也可以看看窗户里的表。或者就算了。
◇ [frame] 照着门框试这扇门。 → ps_boundary_check
  条件：排除 check:pg_shed:ps_boundary_check
◇ [leave] 就让它锁着。 → ps_leave
[ps_boundary_check] 细察：等一下。先看看门和门框之间的缝。
检定：细察 难度 9 可见 → 成功 ps_boundary_ok，失败 ps_boundary_bad
[ps_boundary_ok] 细察：门不是被挤变形了。
效果：设旗 playground_shed_open = true
记录 [pg_shed_open]（来源 亲眼所见，说话人 你）：器材棚的门能被推进去。
下一句：ps_inside
```

| 行 | 写法 | 含义 |
|---|---|---|
| 会话头 | `■ 会话 <id>` | 一段会话。id 不能改，新会话起新 id |
| 触发 | `※ 触发：…` | 只读说明：这段在游戏里由什么播放 |
| 属性 | `属性：默认来源 X｜主观 是/否｜起点 <id>` | 会话级字段 |
| 台词 | `[节点id] 说话人：文字` | 说话人可写 你、旁白、Q、N、B、同学、洞察、细察、回声、臆想、推演、共鸣。**旁白与你导入后都是主角**（游戏没有独立旁白角色） |
| 选项 | `◇ [选项id] 文字 → 目标` | 玩家选项；目标写节点 id，或 `结束` |
| 来源 | `来源：亲眼所见` | 本句覆盖会话的默认来源：亲眼所见／听人说的／记忆里的／想象中的 |
| 下一句 | `下一句：<id>` 或 `下一句：结束` | 不写 = 接着播文档里的下一句；有选项的台词不会往下接 |
| 条件 | `条件：需要 a、b｜排除 c｜取值 k = "v"` | 满足才播这一句（或才列出这个选项） |
| 效果 | `效果：设旗 f = true`、`效果：目标 objective.x（预览）`、`效果：聚焦 set_square` | 设 flag、改目标条、让镜头看向场景里的一件交互物。括号里的目标文字只是预览，导入时忽略。「聚焦」写交互物 id（`interact_id`，如 `set_square`、`q_talk`、`student_talk`）：写在选项下，选中时镜头转过去；写在台词下，这句出现前转过去；都只停留一句台词的时间，然后回到原来的镜头。找不到这个交互物时游戏只警告、不报错 |
| 记录 | `记录 [entry]（来源 X，说话人 Y）：文字` | 写进玩家的记忆列表；entry 全库唯一 |
| 检定 | `检定：细察 难度 9 可见 → 成功 a，失败 b｜加值 f +1` | 掷骰；带检定的台词不写下一句和选项 |
| 仅一次 | `仅一次` | 选项选过后消失 |
| 换行 | `⏎` | 一句台词内部的换行 |

**归属规则：** 一句台词下面的小字都属于这句；`◇` 下面的小字属于这个选项，直到下一句台词或下一个选项为止。所以台词自己的「下一句／效果」必须写在它的选项**之前**。

`※` 开头的行和 Google 文档批注都不导入，可以随便写备注。

## 3. 检视台本

```
■ 检视 pg_return_board
标题：交还板
提示：看交还板
首次：红台阶画的是教学楼墙边的防火门。回后巷走对面的铁栅门。
再看：防火门回教学楼，铁栅门回后巷。
说话人：你
记录 [pg_return_board]（来源 亲眼所见，说话人 你）：……
回想 [entry]：……
```

`首次` 是第一次看时的文字，`再看` 是之后每次的文字，`回想` 是记忆列表里对应条目的补充。同一章节内的检视 ID 必须唯一；重复项会在导入前拒绝，并指出首次与重复出现的行号。不同章节可以使用相同 ID。

## 4. 可以改什么、会被拦下什么

**作者改过的文字就是定稿**（规则原文见 [AGENTS.md](../AGENTS.md)「Author's text（作者文本）」与 [AGENT_PROTOCOL.md](AGENT_PROTOCOL.md) §9）。作者亲手改过的旁白、台词、选项与检视文字，Agent 不得改写、缩短、合并、挪动或「润色」，除非作者明确要求改那一处；连错别字也要作者确认后才改。作者删掉的内容不得恢复，也不得换个 id 重写回来。Agent 可以提问，也可以在作者文本之上补选项和玩法，但新文字一律留给作者写：留空或暂用已有的句子，并在 [对话契约](../data/dialogue_schema/README.md)「Lines pending author review」里登记。改稿里有拿不准的地方（例如小字里混进了正文、格式坏了），先问作者，再导入。

可以：改字；增删台词与选项；改说话人；改跳转；加条件、效果、记录；加新会话（但新会话要有人播放它，请在批注里说明）。

导入时这些会被逐条拒绝，**任何一条出错都不写入任何文件**，报错指出第几行、对应会话或章节；重复检视 ID 会同时列出两处行号：

- 不认识的说话人、来源、能力；
- 同一会话里重复的节点 id、同一句里重复的选项 id、同一章节里重复的检视 id；
- 「下一句」、选项、检定成功/失败指向不存在的台词；
- 起点不存在；最后一句没写「下一句：结束」；
- 主观会话（想象、回忆）里设旗、改目标、检定、`仅一次`，或记录「亲眼所见／听人说的」；
- 目标条写成了文字而不是 `objective.` 键。

导入成功后，id 引用、flag 拼写与语言一致性还会由 CI 的内容测试（`tests/dialogue_content_test.gd` 等）再查一遍。

## 5. 往返流程（维护者）

```bash
python3 tools/story_doc.py export --out build/story_doc   # 每份 .txt + .docx（只用标准库）
# 上传到 Google Drive（转成 Google 文档）；写作者在原处编辑
# 从 Drive 把每份文档导出为 .docx 或纯文本，放进 build/story_doc/returned/
python3 tools/story_doc.py import --dry-run build/story_doc/returned/*.docx
python3 tools/story_doc.py import --pending build/pending_en.json build/story_doc/returned/*.docx
python3 tools/story_doc.py roundtrip                      # 未改动时导出→导入必须零变化
```

- 导入只重写 `zh-CN`；`en` 跟随中文的结构，**中文没改的句子保留原英文**，中文新写或改过的句子列进 `pending_en.json`（附改前中文与改前英文），译完填回 `data/*/en/`。
- 重建的对象沿用原对象的键顺序，所以没改的地方 diff 为零。
- 导入会打印「结构：」摘要（新增／删除的台词、结构变化、顺序变化），PR 描述里照抄，方便审阅。
- `tests/story_doc_test.py` 在 CI 里证明：未改动的导出导入后逐字节一致，常见错误会被拒绝。
