# 离线日志与故障诊断（#224）

这是排障记录，不是存档、玩家阅读日志或遥测。游戏不会上传，不会为诊断发起网络请求，
也不会收集账号、设备标识、系统个人路径、原始错误文本、完整存档、台词、选项、知识条目或检定结果。
目录的绝对路径只在本机设置页展示与交给系统文件管理器，不进日志和导出。旧版若留下
`godot*.log`，本功能不读取、不打包、不删除；不要把它们当作已脱敏的材料分享。

## 添加或读取一个事件

- `OfflineDiagnostics.note("world.transition_refused", {"reason": "scene_missing", "to_location": "corridor"})`：
  通过 `preload("res://scripts/autoload/diagnostics.gd")` 获取 `OfflineDiagnostics`，只从**主线程的低频操作边界**调用。先在 `scripts/diagnostics/event_schema.gd` 登记事件、
  固定英文说明、等级、类别和必要字段。不能传入 `detail`、路径、对象、存档快照或玩家内容。
- 等级 `DEBUG < INFO < WARNING < ERROR`；默认 `INFO` 及以上、所有类别。
  调试可调用 `Diagnostics.set_filter(Diagnostics.LEVEL.DEBUG, ["assets"])`；空类别表代表全部。
  过滤只影响后续入队，不篡改已落盘历史。类别为 `session`、`world`、`save`、`dialogue`、`assets`、`state`。
- JSONL 每行一个 `schema: 1` 记录：`event`（稳定事件 ID）、`level`、`category`、`message`、
  `context`、`at_unix_s`、`last_unix_s`、`repeat`。两时间均为 UTC Unix 秒；时钟调整可能改变时间顺序，
  数组保留写入顺序。同一缓冲里相邻、同 ID、同清洗后字段、间隔 ≤1.5 秒的事件合并计数。
- 只接受字段白名单中的固定枚举、小整数与发布地点表里的 ID。未知字段和值丢弃；
  历史文件也按同一规则重建，绝不原样复制行、路径、消息或嵌套载荷。未知版本或坏行跳过。
- 启动/退出与设置页共用一份 `Diagnostics`。日常每隔约 3 秒只交给一个工作线程写一批，
  无每条写盘。待写最多 64 条，另最多 64 条正在写；写失败保留最新的记录，约 10 秒后重试。
  写日志不再产生日志；失败计数和错误码在玩家导出时可查。
- `user://logs/events-*.jsonl` 每个最多 64 KiB、最多 4 个托管文件（合计 256 KiB），超出轮转最老文件。
  末尾断行不拼接，下次写新卷；读回时跳过残行。正常退出等待在途写入并尽力清空待写缓冲；
  读写权限或磁盘异常时不承诺落盘。崩溃只保留已写成的行，不承诺捕获崩溃栈；强杀、断电不保证。
  同一用户目录应只运行一个游戏进程，不提供多实例同步或持久性事务。

## 玩家导出与解读

从**标题或暂停菜单 → 设置 → 故障诊断**选择「导出诊断（替换上次导出）」；
然后用「打开日志目录」或复制设置页显示的目录，找到 `diagnostics-latest.json`。
导出最多最近 160 条，保留一次手动导出，包含：

- `game_version` / `godot_version` / `os`：导出进程对应的游戏版本、引擎版本及 OS 大类，
  不含 OS 发行版详情；旧文件可能保留自不同构建。发布时沿用 `stamp_release_version.py` 的版本标签。
- `runtime`：导出当下的场景 ID、公开地点 ID、暂停/对话活动及是否等待选项；
  只在游戏内导出有值的布尔进度门 `class_dismissed`、`left_classroom`，不读取完整 flag 表。
  在标题导出时地点为 `null`，不要把它误解为存档位于未知地点。
- `events`：按写入顺序查看问题前的 `world.entered`、`session.scene_changed` 等轨迹，
  再按 `WARNING` / `ERROR` 和 `context.reason` 定位；没有事件不代表没有发生异常。
- `history`：`discarded_this_process` 是本进程缓冲淘汰条数（不是 `repeat` 的总次数）；
  `skipped_units` 是本次读历史时跳过的坏行/文件数，读写错误码 `0` 表示未观察到 I/O 错误，
  `pending_records` 表示随包带出的尚未落到历史文件的记录数；轮转或最近 160 条限制不计为异常。
- `privacy`：随包的包含/排除范围与手动分享说明。地点和门控状态仍能反映游玩进度，
  先用文本编辑器查看，只手动分享 `diagnostics-latest.json`，不要打包存档或整个用户目录。

磁盘/权限不允许写日志时尽量带上内存记录；如果导出目录也完全不可写，设置会明确报失败，
不会跳去另一目录，也不会把数据发到别处。打开目录只是把本地路径交给操作系统；没有桌面文件管理器时可手动打开路径。

## 验证方法

Linux 上先按仓库流程导入项目，再运行 `bash tests/run_offline_diagnostics.sh`。
使用独立临时 XDG 配置/数据：一组用于过滤、去重、轮转、损坏行、内存与不可写夹具；
另一组仅在两个游戏进程之间共享。第一进程由标题进游戏，制造实际存档恢复警告和切场景错误，
点击/按键等价的标题 Quit 退出；第二进程经标题和暂停设置的按钮导出并解析实际写出的 JSON。
断网时可复跑相同步骤；自动检查不验证真实系统文件管理器、Windows 或渲染像素，需人工复核。
