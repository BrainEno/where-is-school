# 美术圣经（Art Bible）

> **英文版为项目规范的基准版本。** 中文阅读版对应 [ART_BIBLE.md](ART_BIBLE.md)。修改时必须同步维护两份文件。

## 视觉主张

**一个具有舞台般空旷感、生活着一群心理特征鲜明人物的表现主义世界。**

where-is-school 是一款文学叙事向的 2.5D 探索游戏。它的视觉语言介于表现主义绘画、图像化插画、手绘痕迹、剧场布景，以及经过刻意设计的 3D 游戏空间之间。

整体方向由四个彼此关联的部分构成：

- **人物——表现主义：** 通过姿态、比例、面部结构、色彩和动作，呈现人物的情绪与心理存在感。
- **环境——图像化与手工感：** 空间可以使用鲜明的色块、松散的轮廓线、手绘痕迹、涂鸦式笔触、粗糙纹理和有意简化的几何结构。
- **室外空间——荒诞的剧场式留白：** 尤其在室外，空间可以像简洁的舞台布景：大片天空与地面、孤立的物件、简化的远景，以及等待或迷失的氛围。
- **对话 UI——融合式构图：** 肖像、文本和选项属于同一幅经过设计的叙事画面，而不是彼此分离的标准化面板。

这个世界可以是不完整的、奇异的，或者在视觉上显得粗粝；生活在其中的人则必须具体而鲜活。

## 艺术参考

以下参考主要用于理解艺术原则和氛围：

- **埃贡·席勒（Egon Schiele）：** 修长的人体、独特的身体比例、暴露而不安的姿态，以及富有表现力的线条。
- **爱德华·蒙克（Edvard Munch）：** 情绪化色彩、心理变形，以及人物与周围空间之间的关系。
- **表现主义绘画与素描：** 主观形体、可见的笔触、不完美的轮廓，以及用于表达内在状态的色彩。
- **涂鸦与非学院派绘画：** 直接的笔触、粗糙边缘、不拘一格的能量和个人化的视觉特征。
- **《等待戈多》：** 极简的剧场布景、暴露而空旷的室外环境、孤立的物件，以及由缺席、等待和不确定性产生的荒诞感。
- **《极乐迪斯科》（Disco Elysium）：** 绘画感人物肖像的艺术独立性，以及可探索的游戏空间与高度艺术化人物图像之间的对比。

这些参考用于启发氛围、构图和技法，而不是固定模板。

## 核心原则

1. **表现力优先于解剖学完美。** 只要能传达人物或情绪，就允许有控制的形体变形。
2. **图像清晰度优先于物理模拟。** 先通过形状、线条、色彩和构图建立画面，再考虑材质复杂度。
3. **留白本身就是叙事。** 空旷可以表达等待、孤独、不确定或迷失。
4. **选择性优先于堆砌。** 重要可交互物品必须清晰、易辨；次要环境保持安静。
5. **粗糙必须有意图。** 不规则边缘、可见笔触、不均匀色彩和不准确透视，只要服务于画面，就可以成为有效选择。
6. **玩法空间必须清晰。** 艺术化变形不能遮挡可行走地面、人物、交互目标、出口或即时导航信息。

## 环境美术方向

### 图像化环境语言

环境应当让人感觉它是被绘制、涂抹或作为图像搭建出来的，而不是对现实进行无遗漏的物理还原。

可以使用：

- 大面积、易辨认的色块；
- 手绘或不规则轮廓；
- 松散线条和可见笔触；
- 选择性加入的涂鸦式痕迹；
- 简化的道具与建筑；
- 色彩区域之间粗粝的过渡；
- 有意的透视偏差和不寻常的空间邻接关系。

图像化不等于画面拥挤。不要在每个表面都铺满笔触，也不要让每件道具都拥有相同的细节量。场景必须保留明确的视觉层级。

### 室外空间：剧场式留白

室外空间是建立游戏视觉身份的重要机会。操场、校园空地、道路、路边空隙，以及居民楼之间的空间，都可以按照简洁的剧场布景来组织。

可以把它想象成一个已经搭建好、只等待少数人物和物件进入的空旷舞台：

- 让天空和地面占据画面中很大的面积。
- 使用简单的地平线，或有意呈现人工感的地面与远景边界。
- 允许一棵树、一张长椅、一根路灯、一块标识牌、一段围栏或一栋远处建筑孤立存在。
- 远处建筑可以稀疏、平面化，或像舞台背景。
- 在画面仍然清晰的前提下，允许不寻常的尺度、间距和透视。
- 可以让人物在广阔的空地中显得很小。
- 不要仅仅为了填满画面而添加环境物件。

最终效果应当带有安静的荒诞感：一个仿佛已经准备好迎接某件事情发生、却一直处在等待中的地方。空旷必须是有意的构图，而不是资产尚未完成。

这是一种空间组织原则，不是要把游戏世界变成字面意义上的剧院。幕布、聚光灯、观众席和传统舞台装饰都不是默认元素。

### 室内空间

室内空间可以比室外保留更多功能性细节，但仍然应当具有选择性和图像化特征。一间教室可以通过少量有意义的元素来辨认——桌椅、黑板、窗户、教师区域和少数剧情相关物品——而不需要堆满所有可能出现的教室用品。

走廊、楼梯、门和房间之间可以出现空间矛盾。即使更大尺度的地理关系不可能成立，玩家仍然应当能够理解眼前的局部空间。

### 材质与表面

优先使用简单材质、绘画表面、大面积色彩变化、手工纹理和有选择的粗粝感。照片级 PBR 细节、无处不在的污垢、锈迹、潮湿感和严重风化，不是本项目必须具备的视觉标志。

表面可以干净、朴素、粗糙或高度图像化。具体处理应当由构图和叙事目的决定。

## 人物美术方向

### 人物设计

人物应当具有独立创作感、清晰的心理辨识度和人的存在感，而不是标准化的游戏人形模型。

可以采用：

- 修长或略微不规则的身体比例；
- 不对称的面部结构；
- 有辨识度的轮廓和服装形状；
- 笨拙、紧张、退缩或其他符合人物个性的姿态；
- 富有表现力的手部、肩部、头部角度和身体重心；
- 不寻常但受到控制的色彩关系。

避免过度夸张的可爱卡通比例，也避免传统学院派写实。形体变形应当揭示人物的某些特征，而不是成为装饰。

### 游戏内 3D 人物

3D 模型和对话肖像承担不同职责。

游戏内模型负责让人物存在于可探索的空间中。优先级如下：

1. 可辨认的整体轮廓；
2. 独特的身体比例；
3. 符合人物特征的姿态和动作；
4. 易于辨认的服装形状与色彩身份；
5. 在游戏镜头距离下足以辨认人物的面部结构；
6. 稳定、经济的动画。

面部细节可以保持简化。不要在 2.5D 摄像机无法呈现的几何细节上投入过多精力。

### 对话人物肖像

对话肖像是高优先级的独立 2D 艺术资产，不是 3D 模型截图、放大渲染图，也不是 3D 模型的自动投影。

肖像明确采用表现主义方向，可以使用：

- 清晰、有力度的可见笔触；
- 变形或不对称的面部比例；
- 非自然的肤色与阴影颜色；
- 不均匀的轮廓和粗糙边缘；
- 具有情绪动机的大胆色彩对比；
- 简化或抽象的肖像背景；
- 根据不同人物设计的独立裁切和构图。

肖像必须让人认得出角色，同时传达某种心理状态。它可以比对应的 3D 模型更加变形、细致或直接地表达情绪。

不同人物不应只是同一套肖像模板换上不同面孔。应当根据人物身份，调整姿态、裁切、笔触、色彩和变形程度。

初期先制作少量有意义的状态，而不是大量差异极小的变体。例如：默认、说话、恼怒、不自在、惊讶或退缩。最终表情数量应由实际对话需求决定。

可编辑源文件和运行时导出图片必须分别保存，并保持清晰的组织方式。

## 色彩方向

色彩应当表达情绪和视觉层级，而不是严格遵循物理材质的真实颜色。

- 环境可以使用受控制的中性、低饱和、暖色或意外鲜明的色块。
- 室外构图可以采用大面积天空色和地面色，并保持远景简洁。
- 持续出现的暖色黄昏可以作为有用的视觉母题，但不要求每个地点都覆盖同一种滤镜。
- 人物肖像可以使用更强烈的对比、不自然的肤色、非现实阴影和带有情绪力量的背景色。
- 可交互物品可以通过选择性的色彩强调提升辨识度。

不要强迫所有场景和人物使用同一套固定配色。应当为不同场景建立局部色彩方案，同时保持整体视觉语言的一致性。

## UI 方向：融合式叙事构图

UI 应当简洁、克制、经过设计，并且易于阅读。对话界面不是把传统角色头像框放在独立文本框旁边。

**人物肖像、对话文本、说话者身份和选项应当共同构成一个融合的画面。**

可以探索以下处理：

- 肖像从屏幕边缘自然进入，或延伸至画面边缘之外；
- 不规则的肖像裁切和轮廓；
- 让肖像色块与对话区域在视觉上产生联系；
- 肖像与文本在构图上相互交错，但不能遮挡阅读；
- 根据人物和情境改变肖像大小与位置；
- 在长篇对话中，为文字调整布局并留出更多空间。

融合不意味着拥挤或混乱。应当保持统一的布局规则和清晰的视觉层级，同时允许有控制的变化。

### 可读性要求

中文长文本是硬性要求。必须保证：

- 舒适的文本宽度与行长；
- 足够的字号和行间距；
- 文字与背景之间有充分对比；
- 对话正文与玩家选项清晰区分；
- 说话者身份容易定位；
- 在支持的分辨率下换行和布局稳定；
- 保留对话记录、文字速度和跳过功能。

当肖像与正文发生竞争时，应当重新调整构图，而不是通过缩小字号或损害阅读体验来解决。

### UI 克制原则

避免不必要的装饰边框、复杂面板、装饰性徽章、过多图标、光泽按钮和厚重渐变。质感应当来自字体、间距、色块、简单线条和受到控制的不规则边缘。

对话记录、物品栏、检查、设置、判定和交互提示等其他界面，也应遵循相同的克制图像语言。

## 摄像机与构图

游戏继续采用受控的 2.5D 摄像机和 3D 环境。

- 保持导航、交互目标和空间关系清晰。
- 使用不对称构图、大面积留白、简化纵深和有意识的色彩分组。
- 在室外场景中，让空旷空间的尺度与玩家的小身影形成对比。
- 通过不可能的连接、尺度变化、重复和空间断裂来产生超现实感。
- 不要为了视觉变形牺牲可游玩空间的清晰度。

## 制作流程

### 环境

1. 首先确定灰盒场景、可行走路线、碰撞和摄像机。
2. 找出少量重要的交互物件和叙事物件。
3. 在添加道具之前，先通过地面、天空、远景和留白确定构图。
4. 建立主要形状和色块。
5. 加入经过选择的手绘痕迹、涂鸦式笔触和表面纹理。
6. 简化或弱化次要物品。
7. 使用实际游戏摄像机检查画面，并确认导航清晰。

### 3D 人物

1. 明确人物的叙事功能和个性。
2. 设计独特轮廓、比例和姿态。
3. 制作经济、易维护的 3D 模型。
4. 建立服装和色彩身份。
5. 只添加在游戏距离下能够看见且有用的面部细节。
6. 在实际场景中测试比例、动画和辨识度。

### 2D 对话肖像

1. 明确已经确认的人物视觉信息，以及仍未确定的部分。
2. 探索少量表现主义肖像方向。
3. 独立于 3D 模型，设计面部、裁切、姿态、配色和笔触。
4. 先完成主要肖像，再制作大量表情变体。
5. 将肖像放入包含真实中文长文本的对话构图中测试。
6. 保留可编辑源文件，并记录资产来源。

### UI

1. 建立肖像、正文和选项融合的对话构图。
2. 使用中文长文本测试，而不是只用占位短句。
3. 测试不同轮廓的肖像和不同人物身份。
4. 验证键盘、鼠标、对话记录、选项和语言切换行为。
5. 测试支持的分辨率和安全区域。

## 技术与资产约束

- 引擎：Godot 4.7.2 Stable 标准版。
- 3D 源文件：Blender。
- 运行时 3D 交换格式：优先使用 glTF 2.0 / GLB，除非有记录在案的其他需求。
- 对话肖像：独立的 2D 资产，并保留可编辑源文件。
- 源文件与优化后的运行时导出文件分开管理。
- 在 docs/ASSET_PROVENANCE.md 中记录创作者/工具、来源、许可证、适用条款，以及人工编辑和审批过程。
- 生成或下载的资产不自动获得商业使用或仓库收录许可。
- 必须在真实 Godot 场景中测试资产，不能只在制作软件中验收。
- 渲染与资产复杂度必须符合项目性能预算。

## 视觉验收清单

**环境**
- 是否具有清晰的图像化和手工绘制语言？
- 场景是否经过构图，而不是杂乱堆砌？
- 重要交互物品是否容易辨认？
- 室外场景是否在适当位置通过留白产生舞台布景式的荒诞感或等待感？
- 玩家是否仍然能够理解可游玩的空间？

**3D 人物**
- 轮廓是否具有辨识度？
- 比例和姿态是否表达人物特征？
- 在实际游戏镜头下是否容易辨认？

**对话肖像**
- 是否明确是一件独立的表现主义作品？
- 是否传达了具体的心理存在感？
- 是否能够辨认出角色？
- 是否拥有自身的构图与笔触，而不是模型渲染图？

**对话 UI**
- 肖像、正文和选项是否构成同一个画面？
- 中文长文本是否易于阅读？
- 布局是否在允许变化的同时保持简洁和统一？

## 最终原则

**这个世界可以是不完整的，但生活在其中的人必须是鲜活的。**

室外空间可以近乎空无，却依然具有强烈的存在感。一棵树、一张长椅、一段围栏或一栋远处建筑，就可能为场景提供全部所需的结构。人物可以具有笨拙的比例、明显变形的面孔和粗粝的笔触，但不应因此变成卡通。

where-is-school 的视觉身份来自三者之间的张力：一个具有表现力和图像感的世界、一座暴露在空旷之中的荒诞舞台，以及那些面孔和姿态比周围空间承载更多情绪的人。


## 当前对话界面（已实现的基线）

当前运行版本的对话阅读界面已在 PR #29 中重新设计并经过测试。本节记录的是现阶段已经存在的实现，是后续设计的制作基线，不取代上文确定的融合式肖像方向。

- 对话以文字为主，呈现在画面左下方的区域，并沿上边缘向场景自然淡出。界面根据当前内容计算尺寸，同时保留环境画面。
- 对话正文是视觉上最大的元素，具有经过控制的行长和较宽松的行间距。
- 说话者姓名承担构图锚点的作用，并使用人物强调色；身份/角色说明保持较小、较低调。
- 叙事来源（亲眼观察、他人转述、回忆或想象）通过克制的细线和小型标签表达，不使用徽章、胶囊标签或高饱和色块。
- 玩家选项以编号文字行的方式呈现在分隔线下方。鼠标尚未指向时保持低调；避免实心按钮、装饰性图标和发光效果。
- 人物对话肖像已经列入计划，但尚未成为正式资产。现有布局在左侧边缘和文字区域上方预留了空间。不要添加占位剪影或伪造的人物头像。

当经过确认的人物肖像作品完成后，应当在当前阅读界面的基础上，逐步实现本美术圣经所规定的肖像与文本融合构图。肖像应当自然地融入场景和阅读界面，而不是被放进传统头像框。必须保留当前实现已经验证有效的特征：必要时以文本为优先的层级、中文长文本可读性、响应式尺寸、清晰的玩家选项、键盘/鼠标交互，以及叙事来源区分。

灰盒人物上方的开发名称标签属于调试工具，不是最终游戏 UI，也不应被视为人物肖像系统的一部分。
