where-is-school — the vertical slice
====================================

Run it
------
Windows x86_64: unzip the whole archive, then double-click where-is-school.exe.
The build is unsigned, so Windows SmartScreen may show "Windows protected your PC".
Only for a build you trust, choose "More info" -> "Run anyway".

Linux x86_64: unzip the whole archive, open a terminal in that folder, then run:

    ./where-is-school

If extraction lost the executable bit, first run `chmod +x ./where-is-school`.
Linux support is experimental: desktop graphics/audio/controller playtesting and
Steam Deck playtesting are unverified. A passing CI export is not a hardware test.
README.txt in the Linux archive has driver troubleshooting and launcher limitations.
Do not run the game as root or with sudo. The Linux build is also unsigned.

macOS (Intel and Apple silicon): unzip the whole archive, then open
where-is-school.app. The build is ad-hoc signed: that is a real code signature,
which is what lets it run on Apple silicon, but it identifies nobody and is not
notarized, so the first open is refused with "cannot be opened because the
developer cannot be verified". Two ways past it, for a build you trust:

  right-click where-is-school.app -> "Open" -> "Open"    (works from the second try on)
  or in a terminal:  xattr -dr com.apple.quarantine where-is-school.app

The quarantine mark is what triggers the warning; removing it from the app you
unzipped is enough. If Gatekeeper still refuses (macOS may cache the refusal),
run the xattr command, then open the app again. Requires macOS 11+ on Intel and
macOS 13+ on Apple silicon. The user-data folder is
~/Library/Application Support/Godot/app_userdata/where-is-school/.

Nothing is installed. The unpacked game folder and the writable user-data folder
are different places. Godot stores progress and preferences per user:

  Windows: %APPDATA%\Godot\app_userdata\where-is-school\
  Linux:   ${XDG_DATA_HOME:-$HOME/.local/share}/godot/app_userdata/where-is-school/
           (XDG_DATA_HOME overrides the usual ~/.local/share location when set)
  macOS:   ~/Library/Application Support/Godot/app_userdata/where-is-school/

The user-data folder contains:

  save.json          your progress (Godot calls this user://save.json)
  save.broken.json   a copy of a save the game could not read, kept for you
  settings.cfg       language, text size and speed, volumes, interface scale, controls
  logs/              recent local technical events (not the dialogue backlog)

Title screen
------------
  Continue   only when there is a readable save: carries on from the last checkpoint
  New game   asks first, then deletes save.json and starts from the beginning
             ("Start" when there is no save yet; nothing is asked then)
  Settings   text size, text speed, volumes, interface scale, fullscreen, language,
             and the controls (keyboard and controller, each can be rebound; "Restore
             default controls" puts everything back)
  Quit

Saving is automatic: the game writes save.json each time you arrive somewhere new and
when the prologue hands you control. There is no save button. Quitting, or going back to
the title screen, keeps the last checkpoint; Continue picks it up there.

If save.json cannot be read, the title screen says so and offers no Continue. Starting a
new game then removes save.json but keeps save.broken.json, so nothing is lost silently.

Controls
--------
  Keyboard and mouse        Controller (Xbox layout)
  WASD / arrow keys         left stick / D-pad      walk (camera-relative); also
                                                    cancels an automatic walk
  left click on the floor   (walk with the stick)   walk there
  left click on a thing     A when it is prompted   walk over and use it (same as E)
  E                         A                       use what the prompt names
  Space / Enter / click     A                       advance a line of dialogue; a
                                                    sentence still typing is finished
  Up / Down + Enter, 1..9   D-pad up / down + A     pick a dialogue option
  Tab                       Y                       open, and close, the log
  Esc                       Start                   pause menu (Resume, Settings,
                                                    New game, Title screen)
  Esc                       B                       back / cancel in any menu
  Shift                     RB                      walk faster
  L                         Back / View             switch English / simplified Chinese
  F11                       right stick click       fullscreen

Every menu works with the keyboard alone (arrows, Enter, Esc) or the controller alone
(D-pad, A, B); the mouse is never required. The prompts name the controller's buttons as
soon as it is used, and the keyboard's again when a key is pressed. Esc is reserved for
the menus and cannot be rebound.

A conversation, once started, is read to its end: there is no way to walk out of one
mid-sentence, which is deliberate for a slice this short and is listed as a limitation,
not a bug.

The mouse cursor changes over anything in reach, and the prompt names the same object
the E key would use.

What this build is
------------------
The end of a milestone, not the end of the story: the slice stops at a gap in the yard's
fence with an end card. The card offers "Start again" (asks first, then begins a new game)
and "Title screen".

Presentation is still in development and has not passed final owner visual acceptance.
The Windows executable has the project icon; the running window may still show the
engine's default icon. Report missing assets or unreadable controls, not just that the
presentation is unfinished.

Reporting something
-------------------
Go to Settings -> Troubleshooting from the title screen or while paused. Choose
"Export diagnostics (replace last export)", then "Open log folder" to find
`diagnostics-latest.json`. The folder path is also shown in Settings. Exporting
works offline and sends nothing. Open the file in a text editor and share only
that file, manually, if you choose. Do not share your save or the whole folder.

The report includes the game and Godot versions, OS family, current scene/room,
a few progression and dialogue-status fields, and up to 160 recent technical
records. It does not include dialogue/choices, saves, usernames, personal paths,
or raw Godot output. Logs rotate and retain a limited history across restarts;
a crash, power loss or forced exit can lose events that had not yet been written.
Older `godot*.log` files are not part of the report and are not sanitized by it.

中文：标题或暂停菜单 → 设置 → 故障诊断。点击「导出诊断（替换上次导出）」后，
「打开日志目录」找到 diagnostics-latest.json。包内包含版本、地点、少量状态与近期事件，
不含存档、台词、用户名、个人路径或引擎原文。请先检查，只手动分享该文件；游戏不会发送。

If you are the owner: docs/PLAYTEST_CHECKLIST.md in the repository is the list this build
is meant to be played against, with what to write down. If something breaks, the useful
details are where you were (room), what you did, and what you expected — the game has no
telemetry and sends nothing anywhere.
